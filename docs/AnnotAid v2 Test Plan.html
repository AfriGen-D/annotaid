Can a small team do the real job?

One focused journey from account approval to a submitted, exportable paper. Mark each checkpoint and write only what surprised you or failed.

6 / 11 6 passed

Run details

Use one manager and one curator account.

Keep it simple: use one small project and 1–3 papers. If a checkpoint fails, record what you clicked, what happened, and any visible error. Then continue where possible.
01

Access and approve a curator

Anonymous access is closed; a real user can get in.

  1. Open the app signed out. Confirm it sends you to sign in.
  2. Request an account for the curator. Try signing in before approval.
  3. As superadmin, approve the request; then sign in as the curator.
  4. Pending users are refused; approved users reach the home page.
02

Create a project and add the curator

The team can reach the same workspace, and outsiders cannot.

  1. As a manager, create a small project from a config file or from scratch.
  2. Open Team, make an invite link, and use it as the curator.
  3. Confirm both users see the project and the curator cannot see manager-only controls.
  4. The curator joins once and can open the project without managing it.
03

Add papers

The manager can build a usable work pool.

  1. As manager, add 1–3 papers by PMID. Include a duplicate if convenient.
  2. Close the add-papers window while the job runs, then check Jobs.
  3. If a PMID has no downloadable PDF, try its offered PDF-upload route.
  4. Every PMID has a clear outcome; added papers appear in the pool and duplicates are harmless.
04

Assign and claim work

A paper has one clear owner.

  1. As curator, claim a paper from Pool.
  2. Confirm it moves to My papers and becomes editable.
  3. As the manager or another user, open that paper and confirm it is read-only unless reassigned.
  4. Only the assignee can change the paper; assignment is obvious to everyone.
05

Extract and curate values

The core research workflow works end to end.

  1. As manager, start AI extraction for a paper and leave the page while it runs.
  2. Return through Jobs; open the completed paper as its curator.
  3. Edit one extracted value, add or change one group item, and confirm values.
  4. Reload the page and check the edits, confirmation, evidence, and editor name remain.
  5. The job survives navigation and the curator's saved decisions survive reload.
06

Finish and reopen a paper

The workflow closes safely and mistakes are recoverable.

  1. As curator, submit the paper and confirm it becomes read-only.
  2. As manager, reopen it and confirm the action appears in its history.
  3. Finished work is locked; a manager can reopen it without losing curated data.
07

Export and recover

The useful output and a recoverable copy both exist.

  1. As manager, export CSV and spot-check the curated paper.
  2. As superadmin, open Admin → System and run Back up now.
  3. Confirm the backup time updates and no new server error appears.
  4. Exports contain the work and the app reports a successful database backup.
08

Retest the simplified project setup

Managers define research fields; admins define AI infrastructure.

  1. As superadmin, set the model, default model, and PDF processing under Admin → System.
  2. As manager, create a project: define paper-level features first, then one optional repeating group, then review the prompt.
  3. Confirm project creation and shared config files do not ask the manager or curator to choose models or OCR.
  4. Research schema belongs to the project; operational AI settings exist once, under superadmin.
09

Retest two-pass variant extraction

AI discovers row IDs; a curator controls what pass 2 curates.

  1. Use a project with one repeating group and add a paper containing several identifiers (ideally mixed dbSNP, EVA, HGVS, or haplotype forms).
  2. As manager, launch Pass 1 · Identify repeat-group entries immediately after loading the paper.
  3. Confirm extraction pauses: no curated values exist yet, and the assigned curator sees all proposed IDs with short evidence quotes.
  4. As curator, correct/add/remove IDs, approve the list, and confirm pass 2 starts. Reload and verify every approved ID has one row.
  5. Multiple IDs survive; pass 2 cannot start before assignee review and never invents extra rows.
10

Retest abstract-only evidence

Abstract fallback remains a usable curation surface.

  1. Enable abstract extraction for the project and import a PMID with no available full-text PDF but a PubMed abstract.
  2. Run the appropriate AI pass and open a value that has an evidence quote.
  3. Use previous/next evidence and click the value; also select abstract text for a manual evidence edit.
  4. The abstract is readable in the viewer, matching text highlights, navigation says “found,” and selection works.
11

Retest the reduced MVP interface

The removed choices stay removed and the shortcuts are where expected.

  1. On a project card, confirm the manager has Manage team.
  2. Inside a project, confirm there is no account/sign-out menu, paper x/x count, model/OCR picker, Exclude, or Unextractable.
  3. Confirm the only project export is CSV and the database backup remains in Admin → System.
  4. The curator view is focused on claiming, reviewing, curating, and submitting work.
